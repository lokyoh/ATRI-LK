# 群聊模式与用户系统常识

> 文中指令前缀以 `/` 为例，实际前缀由机器人配置决定。

## 什么时候会被回复

- **Agent 聊天默认是关闭的**，且**只对白名单群生效**（配置项：`Agent聊天开关` + `聊天白名单`）。机器人在群里的日常发言通常是普通关键词/图片/语音匹配，而不是 Agent 对话。
- 触发关键词（默认 `ATRI`、`atri`、`亚托莉`、`Atri`、`萝卜子`）会唤醒亚托莉。
- 群聊里 **@ 机器人**或喊关键词才会得到对话回复；不是每句话都会被接。
- 还有**主动聊天**开关与独立白名单，两者需同时满足才会主动开口。
- 群聊消息有优先级与阻塞顺序；其他插件的指令（签到、农场、钓鱼等）会优先于 Agent 聊天处理。
- 私聊与群聊的可用功能不同：**发送表情（send_face）只在 OneBot 适配器的会话里可用**，QQ 官方机器人适配器下该功能不可用。

## 用户绑定（为什么有些功能用不了）

- 大多数 LK 玩法（签到、投喂、运势、农场、钓鱼、宠物）需要用户**已绑定 LK 账号**；未绑定时机器人会给出绑定提示。
- 绑定后才有稳定的 `user_id`，用户的等级、经验、ATRI币、好感、背包、农场、钓鱼与宠物数据都挂在它下面。
- 所以用户说"提示我去绑定"时，正确答复是引导绑定，而不是重试指令。

## 记忆体系

亚托莉对用户有三层记忆，**都按 user_id 存储**：

| 类型 | 内容 | 用户可见方式 |
|---|---|---|
| 用户画像（profile） | 长期个性化信息：兴趣、偏好、称呼等 | 由 agent 通过 `user_profile` 功能查询/修改 |
| 长期记忆（memory） | 最多 11 条带日期的临场记忆，先入先出 | `/聊天.查看记忆` 查看，`/聊天.删除记忆 <序号>` 删除 |
| 语义记忆（embedding 记忆库） | 向量化的历史事实，可按语义检索 | 由 agent 通过 `get_memories` / `access_memory` 检索与强化 |

- **记忆条目都带时间戳**，新增记忆超出上限会挤掉最早的。
- 用户问"你记得我吗 / 我之前说过什么"时，应调用 `get_memories` 检索，而不是凭空作答。
- 用户明确要求"忘掉某条记忆"时，可以帮他删除（长期记忆按序号，或说明他能用 `/聊天.删除记忆` 自己删）。
- 词语解释表（explanations）是另一套机制：管理员用 `/聊天.添加解释 词语 解释 重要度` 补充专有名词，重要性随数字增大。

## 其他常用查询入口

- `/帮助`：框架的「帮助」服务会自动列出所有已注册指令与服务；用户问"有哪些指令/怎么用"时，这是最可靠的答案来源。
- 每个玩法服务的说明可以通过**服务信息查询**获取，包含该服务的指令与文档。
- 当用户问某个**具体玩法怎么用**时，优先查看对应技能（签到/投喂/运势、农场、钓鱼、宠物），那里有详细的指令与机制。

## 回答这类问题的要点

- 不要臆造指令名与参数：不确定就先用功能查询（服务信息、指令信息、技能）确认。
- 涉及用户数据（等级、钱、好感、农场、鱼、宠物）时，用对应的查询功能或引导用户自己发指令查看，不要编造数值。
- 用户抱怨"没反应"时，先区分三类原因：**功能没开启/不在白名单**、**未绑定账号**、**冷却中或输入格式错误**。
