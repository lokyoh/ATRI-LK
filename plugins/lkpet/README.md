# lkpet · 赛博宠物养成系统

ATRI-LK 的宠物插件：养成、轮回、肉鸽爬塔统一挂在「宠物」服务下，数据全部走
`database.py` 注册的表。

- **无种族、无进化**：所有宠物共用一套模型，个体差异来自性格与随机资质。
- **天为基本单位**：年龄、寿命、状态衰减、行动点重置全部以个人日推进。
- **每人仅一只**：不可更换、不可多养、不可交易。
- **轮回必须主动确认**：日结算只会提示条件，绝不自动终止或重置宠物。

## 指令

**所有指令都在主命令 `宠物` 之下**，写作 `/宠物.xxx`。这样做的原因：`休息` /
`技能` / `天赋` / `轮回` / `特权` 这类通用词如果占据顶层，任何后续插件想用同一个词都会
撞车 —— 而 nonebot 对**重复的指令前缀只保留第一个**，第二个会被静默丢弃（只打一条 warning）。

> **前缀是动态的**：本文里的 `/` 只是字面示例。运行时实际前缀由
> `ATRI.bot.BotUtils.get_command_start()` 决定（读 `conf.BotConfig.command_start`，
> 可能是 `/`、`！` 等）。插件的全部用户可见文案在 `utils/texts.py` 出口统一做前缀替换
> （`apply_command_start`），改前缀配置无需改任何文案；文档示例仍写作 `/`。

## 配置

### 插件设置 `config.py`

按 `plugins/lkchat/config.py` 的模式定义，**每个字段都有默认值**，用户不改任何一项也能跑：

| 字段 | 默认 | 说明 |
|---|---|---|
| `enable` | `True` | 养成系统总开关 |
| `settle_notify` | `True` | 日结算后是否推送通知（供定时任务使用） |
| `settle_check_hour` / `settle_check_minute` | `0` / `0` | 每日检查日结算的时间 |
| `notify_groups` | `[]` | 接收通知的群号，留空则不主动推送 |
| `tutorial_enabled` | `True` | 是否启用新手引导 |

**游戏数值不在这里**，全部只放在 `res/data/lkpet/config/*.yaml`，避免两处重复定义。

### 亲密度

量表是 **0–1000**（比常见设计放大 10 倍），这样每日衰减的小数系数乘上基础值 10 之后
仍是整数。**互动获得**：喂食 / 玩耍 / 洗澡 / 休息 统一掷 **3d10**（骰子规格外置
`interactions.yaml` 的 `affection_roll`）；800 以上收益减半、封顶 1000（`core/affection.py`）。
**每日衰减**按「照护是否到位」判定：饥饿 / 心情 / 清洁低于阈值、疲劳高于阈值各算一项
未满足，未满足 1 / 2 / 3 / 4 项分别乘 `1.0 / 1.1 / 1.3 / 1.5`，全部满足则不衰减。
判定用的是当天状态衰减**之后**的数值。

## 附加玩法

### 肉鸽爬塔（`/宠物.肉鸽`）

- **100 层 = 5 个区域 × 20 层**：青草平原 → 迷雾森林 → 熔岩洞窟 → 冰封王座 → 深渊之巅，
  每区域一个主题，敌人数值跨区**翻倍**（基础 HP 40 → 1000）。
- **每区域第 10 层为固定遗物奖励层**（三选一，**仅本局生效**）；**每区域末层只有一个内容：随机一个候选首领**
  （seed 可复现），击杀掉**该 Boss 的专属遗物**（一个 Boss 对应一件），首通另给装备/技能/称号（首领层 20/40/60/80/100）。
- **精英遭遇**：每区域 5 个精英备选（共 25 个）；区域前 5 层不生成、**每区域至多 4 次**、**倒数第二层必出**
  （30% 概率 + 保底，区域级 seed 复现）；精英 ×1.6 属性、掉落 ×2，战斗行预告「⚠️ 精英出没」。
- **首领前一层只有一个内容：回血补给事件**（无三选一；回血按区域倍率放大）——吃完直接前进打首领。
- **战斗选中即开战**（普通/精英遭遇没有二次确认；首领报告随机结果后回复 1 开战）。
- **战斗机制（ATB）**：个人攻击条上限 100、每轮攒 `gauge_rate_mult × spd`，先满者出击——**速度决定出击频率**；
  技能有 `cooldown`（单位=计时条周期），**战斗计时条每轮 +10、每满 100 全技能冷却 -1**（预留计时 Buff 递减位）；
  战报展示双方出击次数。
- 每区域 **30 个事件**、**10 种小怪**（共 150 事件 / 50 小怪），事件只从本区域**未触发过**的池里抽
  （一次 run 每个事件只触发一次）。**选项历史剧透**：玩家选过的事件选项跨 run 记录在
  `PETROGUE.CHOICES`（`"事件id:编号"`，仿 RELICS 图鉴，随 ROGUE_VERSION 升到 2 时迁移补列），再次遭遇
  同一事件时，选过的选项文本后自动附 `[实际效果]` 标注（如 `1. 缒下去探看 [HP-14，金币+20]`；
  无效果选项标 `[没有效果]`，遗物掉落带属性说明；补给层回血按区域倍率放大后标注）——
  没选过的选项保持悬念。
- **怪物特点**：50 只小怪与 25 个精英各自带 0-2 个特点（`roguelike.yaml` 的 `monster_traits` 定义块
  + `monsters/elites[].traits`），遭遇与战报中以 `名称（血厚，速慢）` 标注——**没有特点的怪不标注**。
  数值特点（血厚/薄、攻高/低、防高/低、速快/慢，即 `*_mult` 乘区）在生成时作用于当层公式
  （精英/首领倍率之前，单次叠乘；首领不叠小怪特点）；行为特点直接进入 ATB 战斗：
  `群袭`（一次出击 2 击、每击 0.6×）、`高暴击`（25% 概率 ×`battle.crit_mult`）、
  `吸血`（造成伤害的 30% 回复自身，封顶生成时生命）、`棘刺`（我方打出伤害的 20% 反弹到局内生命，
  不致死）。同区域小怪特点签名 ≥6 种（冒烟校验「不是同一个模子刻出来的」）。
- **敌方专属技能（只有精英与首领有）**：小怪永远只有普攻；技能表**单独放在 `roguelike.yaml` 的
  `enemy_skills`**（共 30 个，分 物理猛击系 / 蓄力终极技 / 状态与削弱系 / 自我强化系 / 召唤系 五组；
  **故意不写进 `skills.yaml`**，那是宠物自己的技能表），精英在 `elites[].skills` 引用、首领在
  `bosses[].skills` 引用。字段与宠物技能同口径：`power`（伤害 = atk × power / 30，与小怪普攻同一基准）、
  `strikes`、`crit_rate`、`leech`、`heal`、`self_buff`、`debuff`、`dot`、`charge`、`interrupt`、`summon`、
  `cooldown`（单位 = 计时条周期）、`mp_cost`、`priority`（越大越优先，同级比 `power`）。
- **敌方 MP**：独立资源池，入场即满（`battle.enemy_mp`：基础 50，精英 ×1.6 / 首领 ×2.4 / 召唤物 ×0.6），
  之后**计时条每满一次回复 `regen`（8 点）**——与技能冷却同一节奏。
- **蓄力终极技（可打断）**：敌方花一次行动开始蓄力，**蓄力期间可被打断**：蓄力期间我方对它造成的
  **累积伤害** ≥ 自身生命上限 × `interrupt` 即取消蓄力，否则再过 `charge` 次行动释放。例：精英 铁角原牛
  的「冲锋撞角」（power 72、charge 2、interrupt 0.16）——打断窗口就是这套机制留给玩家的真实战术空间。
- **形态 / 阶段（`enemy_phases`）**：生命比例 ≤ 该阶段 `at_hp` 时触发**一次**（每个阶段各自只触发一次），
  施加**永久**属性乘区，可选附加回血与追加技能；战报会播报进入的形态（暴怒 / 狂乱 / 坚壁 / 疾走 / 不灭 /
  垂死挣扎）。精英用单个形态（`elites[].phase`，如 雾隐枭人 → 疾走），首领用列表（`bosses[].phases`）。
  例：深渊首领 无名之影 `skills: [e_summon_shade, e_soul_reap, e_shadow_raid]`、
  `phases: [ph_swift, ph_berserk]`（先 疾走 再 狂乱）。
- **召唤与转火**：召唤系技能往场上加援军，援军与召唤者并肩作战、**召唤者倒下时一并消失**；我方自动攻击
  **存活敌人中生命比例最低者**（比例相同优先首领），所以**先清召唤物再打首领**才是正解；同时存在的敌人
  数由 `battle.max_units`（4）封顶，超出则不再召唤。
- **削弱与持续伤害（DoT）**：削弱时长单位 = 计时条周期数（`debuff.rounds`）；DoT 每轮结算一次、
  **自身不致死**（最多把局内生命压到 1），所以只有正面攻击能结束本局。
- **逐回合战报**：战报新增最近若干轮的逐条回放——谁施放了什么技能、蓄力进度与是否被打断、进入形态、
  召唤、我方转火、暴击、吸血与 DoT 结算，输赢原因一眼可见；回放条数上限 `battle.log_limit`（12，0 = 关掉）。
- **战前预告**：精英 / 首领遭遇会先列出对手的专属技能（附 `蓄力 N 回合，累积伤害可打断` / `召唤 N 只` /
  `削弱我方` 等标注）与形态阈值（`形态名（生命 ≤N%）`），进场前就知道该防什么。
- **遗物系统（95 件，仅本局生效）**：普通 35（遗物层三选一池）+ 稀有 15 + 商店专属 20 + 事件专属 10 +
  Boss 专属 15（`rogue_relics.yaml`），本局获得即时生效；`PETROGUE.RELICS` 只作「见过的遗物」**图鉴**，
  不提供加成。效果为战斗属性/掉落乘区、暴击率、商店折扣、事件掉落、首领战后回血等，**不改养成数据**。
  所有遗物展示位（三选一 / 获得回执 / 商店货架 / 路线预览 / 进度列表）名称后自动附**紧凑属性说明**
  （如 `微光护符（攻击+6）`、`傀儡之心（防御+15%，生命上限+10%）`），由 `core/roguelike.py` 的
  `relic_effect_note()` 按 `effect` 键实时生成——不需要在 YAML 里另写一份。
- 局内生命 / 金币 / 增益只存在于 run 状态，**只在结算时刻**写回成就点与首通奖励。
- **遗物商店**：区域前 5 层不刷出；货架固定 3 件 = 普通 1 + 稀有 1 + 商店专属 1（排除本局已持有），
  价格按稀有度 `shop.tier_price`（25/60/50）；商店只卖遗物，回血由事件与补给承担。
- **行动点**：**仅入场消耗 3 点**，推进每层 0 点（打到哪算哪，明天再来）。
- **养成接入**：战斗读取 `pet.attributes`（天赋加成直接生效）；主动技能自动施放 ——
  治疗技能血量 <50% 优先，伤害技能按「威力 × 熟练度 ÷ 30」换算攻击系数且**施放即涨熟练度**，
  每技能有 `cooldown`（计时条周期，每满 100 全体 -1）；**被动技能 6 个**（蛮力/铁壁/疾风血脉/魔力源泉/
  巨心/战斗直觉）占用 3 个被动槽，按等级解锁，提供攻/防/速/MP/局内生命/暴击率加成。
- 数值全在 `roguelike.yaml` + `rogue_events.yaml` + `rogue_relics.yaml`：**改数值只动 YAML**
  （精英/首领技能与形态见 `roguelike.yaml` 的 `enemy_skills` / `enemy_phases`），
  用户可见文案统一在 `texts.yaml` 的 `rogue` 块，代码里不写死。

## 数据表

数据库为 `data/sql/lkbot.db`，`database.py` 是以下四张表的唯一注册方：

| 表 | 主键 | 说明 |
|---|---|---|
| `PETDATA` | `ID` | 宠物主表（`NAME` / `INSTRUCTION` + 全部养成字段；遗留列 `LOVE` 不读取） |
| `PETREINCARNATION` | `PLAYER_ID` | 轮回与成就点 |
| `PETBIOGRAPHY` | `PLAYER_ID` | 传记 |
| `PETROGUE` | `PLAYER_ID` | 肉鸽进度：历史统计、首通解锁、遗物图鉴（RELICS）、事件选项历史（CHOICES，跨 run）、进行中的 run |

> **遗留表**：已部署库中的 `PETTRPG` 表（跑团系统遗留）暂时保留在磁盘上，代码不再注册。
> 下次数据库迁移时执行 `DROP TABLE IF EXISTS PETTRPG` 清理，详见 `database.py` 头部的「数据库变更计划」。

**迁移机制**：每张表带版本号（`PETDATA_VERSION` = 1，`ROGUE_VERSION` = 2）。加载时版本号
与库中记录不一致就跑对应的 `update_*_db`：它**不看版本号本身**，而是读 `PRAGMA table_info`
把所有缺失的列 `ALTER TABLE` 补齐（幂等，可重复执行），然后把版本号写为新值。
**改表结构必须同步提升版本号**，否则已到当前版本的库会因"版本相同"跳过迁移、拿不到新列。
`PETDATA` 迁移同时把 `ADOPTED_AT` / `CYCLE_STARTED_AT` / `LAST_SETTLEMENT_AT` 的空值填成迁移
时刻（用 `ATRI.utils.datetime.now()`，与插件其余部分同一时区）。

- **亲密度只有一个来源**：`AFFECTION`（0–1000 量表）；遗留列 `LOVE` 原样留在表里，
  不换算、无代码读取，通用映射层按实际列名取数会自动跳过它。
- **存量宠物首次被读取时**会补全无法由 SQL 计算的字段（属性依赖 `pet.yaml`）：
  `QUALIFICATION`（随机 0.90~1.10）、`ATTRIBUTES`（按等级与资质算出）与等级对应的技能，
  补完立刻落库；存量宠物不弹新手引导。
- `PETDATA.ID` 与模型字段 `player_id` 的差异由 `TABLE_FIELD_ALIASES` 兜住。

`handlers/events.py` 的两个监听器必须是**同步函数**（ATRI 的 `BaseEvents` 拒绝协程），
所以 `database.py` 另外提供了同步的 `load_pet_name` / `load_pet_names`。

## 已知边界

- `achievements.yaml` 只有目录格式，**没有任何代码读取**：任务书 §0 的 15 个 Step 没有
  「成就系统」这一步，§9 也没有它的规范。等立项时直接沿用该目录格式即可。
- 参数校验类提示（性格不合法、行动点不足、属性名错误等）仍在代码里，属于校验信息而非展示文案。
- 轮回的等级门槛只拦「提前主动轮回」；寿命已尽或已满级属于自然终结，即使等级不足也放行，
  否则低等级宠物在寿命结束后会永远无法轮回。
- `/宠物.聊天` 受框架的 `is_chat_switch_on` / 安全模式 / 测试模式 / 绑定检查约束；
  插件自身的 `enable` 是额外的总开关。
