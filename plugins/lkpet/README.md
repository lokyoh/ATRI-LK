# lkpet · 赛博宠物养成系统

ATRI-LK 的宠物插件。原「聊天宠物」的指令、`pet_chat.py`、`pet_data.py` 已**全部并入本插件的新体系**：
数据统一走 `database.py` 的 `PETDATA`，不再有独立的旧模块与内存缓存。

- **无种族、无进化**：所有宠物共用一套模型，个体差异来自性格与随机资质。
- **天为基本单位**：年龄、寿命、状态衰减、行动点重置全部以个人日推进。
- **每人仅一只**：不可更换、不可多养、不可交易。
- **轮回必须主动确认**：日结算只会提示条件，绝不自动终止或重置宠物。

## 指令

**所有指令都在主命令 `宠物` 之下**，写作 `/宠物.xxx`。这样做的原因：`训练` / `休息` /
`技能` / `天赋` / `轮回` / `特权` 这类通用词如果占据顶层，任何后续插件想用同一个词都会
撞车 —— 而 nonebot 对**重复的指令前缀只保留第一个**，第二个会被静默丢弃（只打一条 warning）。

> **前缀是动态的**：本文里的 `/` 只是字面示例。运行时实际前缀由
> `ATRI.bot.BotUtils.get_command_start()` 决定（读 `conf.BotConfig.command_start`，
> 可能是 `/`、`！` 等）。插件的全部用户可见文案在 `utils/texts.py` 出口统一做前缀替换
> （`apply_command_start`），改前缀配置无需改任何文案；文档示例仍写作 `/`。

### 由旧插件并入的指令

功能来自合并前的聊天宠物插件，指令名同样收进 `宠物` 命名空间。

| 指令 | 说明 |
|---|---|
| `/宠物 <内容>` | 与宠物聊天（LLM），名字与设定取自数据库 |
| `/宠物.好感度` | 显示亲密度（0–1000）与档位 |
| `/宠物.改名 <新名字>` | 改名，聊天人设立即跟着变 |
| `/宠物.设定 <设定>` | 修改聊天人设 |
| `/宠物.列表` | ADMIN，列出本群有宠物的成员 |
| `/宠物.全部` | MASTER，列出所有宠物 |

原来的两步追问流程（先问名字、再问设定）已合并为一次性参数；设定可以省略，之后用
`/宠物.设定` 补即可。

**合并前的 `/pet.xxx` 写法不再保留** —— 命令表以上面这份为唯一准。旧插件时期用户习惯的
`/pet.改名` 之类需要重新适应；这是为了让整个插件只有一套命名规则。

`/帮助` 由框架的「帮助」服务提供，会自动列出以上指令，插件本身不注册同名指令。

> **注意**：`/宠物` 聊天指令拥有 `宠物` 前缀，所以任何**不带点**的 `/宠物XXX`（例如旧写法
> `/宠物状态`）都会被当作对宠物说的一句话交给聊天处理，而不会报"指令不存在"。
> 这是 nonebot 最长前缀匹配的自然结果，也是把聊天放在 `/宠物` 的代价。

## 配置

### 插件设置 `config.py`

按 `plugins/lkchat/config.py` 的模式定义，**每个字段都有默认值**，用户不改任何一项也能跑：

| 字段 | 默认 | 说明 |
|---|---|---|
| `enable` | `True` | 养成系统总开关 |
| `settle_notify` | `True` | 日结算后是否推送通知（供定时任务使用） |
| `settle_check_hour` / `settle_check_minute` | `0` / `0` | 每日检查日结算的时间 |
| `notify_groups` | `[]` | 接收通知的群号，留空则不主动推送 |
| `tutorial_enabled` | `True` | 是否启用新手引导 |

**游戏数值不在这里**，全部只放在 `res/data/lkpet/config/*.yaml`，避免两处重复定义。

### 亲密度

量表是 **0–1000**（比常见设计放大 10 倍），这样每日衰减的小数系数乘上基础值 10 之后
仍是整数。衰减按「照护是否到位」判定：饥饿 / 心情 / 清洁低于阈值、疲劳高于阈值各算一项
未满足，未满足 1 / 2 / 3 / 4 项分别乘 `1.0 / 1.1 / 1.3 / 1.5`，全部满足则不衰减。
判定用的是当天状态衰减**之后**的数值。

## 附加玩法

### 肉鸽爬塔（`/宠物.肉鸽`）

- **100 层 = 5 个区域 × 20 层**：青草平原 → 迷雾森林 → 熔岩洞窟 → 冰封王座 → 深渊之巅，
  每区域一个主题，敌人数值跨区**翻倍**（基础 HP 40 → 1000）。
- **每区域第 10 层为固定遗物奖励层**（三选一，**仅本局生效**）；**每区域末层只有一个内容：随机一个候选首领**
  （seed 可复现），击杀掉**该 Boss 的专属遗物**（一个 Boss 对应一件），首通另给装备/技能/称号（首领层 20/40/60/80/100）。
- **精英遭遇**：每区域 5 个精英备选（共 25 个）；区域前 5 层不生成、**每区域至多 4 次**、**倒数第二层必出**
  （30% 概率 + 保底，区域级 seed 复现）；精英 ×1.6 属性、掉落 ×2，战斗行预告「⚠️ 精英出没」。
- **首领前一层只有一个内容：回血补给事件**（无三选一；回血按区域倍率放大）——吃完直接前进打首领。
- **战斗选中即开战**（普通/精英遭遇没有二次确认；首领报告随机结果后回复 1 开战）。
- **战斗机制（ATB）**：个人攻击条上限 100、每轮攒 `gauge_rate_mult × spd`，先满者出击——**速度决定出击频率**；
  技能有 `cooldown`（单位=计时条周期），**战斗计时条每轮 +10、每满 100 全技能冷却 -1**（预留计时 Buff 递减位）；
  战报展示双方出击次数。
- 每区域 **30 个事件**、**10 种小怪**（共 150 事件 / 50 小怪），事件只从本区域**未触发过**的池里抽
  （一次 run 每个事件只触发一次）。
- **遗物系统（95 件，仅本局生效）**：普通 35（遗物层三选一池）+ 稀有 15 + 商店专属 20 + 事件专属 10 +
  Boss 专属 15（`rogue_relics.yaml`），本局获得即时生效；`PETROGUE.RELICS` 只作「见过的遗物」**图鉴**，
  不提供加成。效果为战斗属性/掉落乘区、暴击率、商店折扣、事件掉落、首领战后回血等，**不改养成数据**。
- 局内生命 / 金币 / 增益只存在于 run 状态，**只在结算时刻**写回成就点与首通奖励。
- **遗物商店**：区域前 5 层不刷出；货架固定 3 件 = 普通 1 + 稀有 1 + 商店专属 1（排除本局已持有），
  价格按稀有度 `shop.tier_price`（25/60/50），原道具货架已下架（回血由事件与补给承担）。
- **行动点**：**仅入场消耗 3 点**，之后推进不再消耗（打到哪算哪，明天再来）。
- **养成接入**：战斗读取 `pet.attributes`（天赋/训练的加成直接生效）；主动技能自动施放 ——
  治疗技能血量 <50% 优先，伤害技能按「威力 × 熟练度 ÷ 30」换算攻击系数且**施放即涨熟练度**，
  每技能有 `cooldown`（计时条周期，每满 100 全体 -1）；**被动技能 6 个**（蛮力/铁壁/疾风血脉/魔力源泉/
  巨心/战斗直觉）占用 3 个被动槽，按等级解锁，提供攻/防/速/MP/局内生命/暴击率加成。
- 数值全在 `roguelike.yaml` + `rogue_events.yaml` + `rogue_relics.yaml`。

### 跑团（`/宠物.跑团`，COC 风格 d100）

- **六维**（STR/CON/DEX/POW/INT/APP，3d6×5）+ 百分比技能，与养成五维**互不覆盖**（独立表 `PETTRPG`）。
- d100 六档（大成功/极难/困难/常规/失败/大失败），团后成长检定 `d100>技能 → +1d10`（上限 95）。
- **9 个剧本**：单人 5 个（雨夜庄园 / 雾谷古井 / 孤港灯塔 / 末班列车 / 雾都夜市）按序推进；
  多人 3 个（荒村客栈 / 商队护送 / 古庙封印）在群内 2–5 人组队、队长代提交、全员 DEX 序检定；
  短团本 1 个（废矿探秘）≤30 分钟随开随玩。
- 剧本场景图全在外置 `trpg_chapters.yaml`，规则与奖励在 `trpg.yaml`；**每章 10–14 个场景、3–7 个结局、
  多条检定分支**，场景文本为多句氛围描写，全部场景可达（无死内容），关键抉择写入传记。
- **混合 GM**：编号/关键词/技能名命中走模板（零成本零延迟）；**未命中的自由文字行动交给 LLM 裁定**
  （限定技能名/难度/成败叙事），LLM 超时或失败自动回退模板提示——**LLM 挂了团照样能跑**。
- **结局有代价**：终局场景带 `outcome: good|bad` 标记（共 11 个坏结局）——坏结局**不发成就点**，
  成长与传记（失手记忆）照常。

## 数据表

复用 ATRI-LK 原有数据库（`data/sql/lkbot.db`），`database.py` 是以下五张表的唯一注册方：

| 表 | 主键 | 说明 |
|---|---|---|
| `PETDATA` | `ID` | 扩展既有表；保留原有 `NAME` / `INSTRUCTION` / `LOVE` |
| `PETREINCARNATION` | `PLAYER_ID` | 轮回与成就点 |
| `PETBIOGRAPHY` | `PLAYER_ID` | 传记 |
| `PETROGUE` | `PLAYER_ID` | 肉鸽进度：历史统计、首通解锁、遗物图鉴（RELICS）、进行中的 run（含本局遗物） |
| `PETTRPG` | `PLAYER_ID` | 跑团卡（六维/技能）与会话；组队会话用 `party:<群号>` 行 |

**迁移**：`PETDATA_VERSION` 为 1。首次加载时若表版本不是 1，`update_pet_db` 就会被调用，
它**不看版本号本身**，而是读 `PRAGMA table_info` 把所有缺失的列 `ALTER TABLE` 补上，
最后把版本号写成 1。

> 版本号只是"要不要跑迁移"的开关，不决定补哪些列。你的库现在是 0，所以是 0→1 一次跳完。
> 之后如果再改表结构，需要**再次**提升版本号，否则已经到过 1 的库会因"版本相同"而跳过迁移，
> 拿不到新增的列。

并把 `ADOPTED_AT` / `CYCLE_STARTED_AT` / `LAST_SETTLEMENT_AT` 填成迁移时刻（用
`ATRI.utils.datetime.now()`，与插件其余部分同一时区）。旧数据不会丢失。

**好感度不做迁移**：旧 `LOVE` 是聊天时代的 0–100 好感，与新养成的 0–1000 亲密度不是同一套语义
（判定规则、档位、加成全不同），直接 ×10 沿用等于凭空给出高亲密。所以**旧宠物的 `affection` 一律从 0 开始**。
`LOVE` 旧列原样保留在表里（不换算、也不清空），但已无代码读取它。

**旧宠物首次被读取时**会补全迁移时无法计算的部分（属性依赖 `pet.yaml` 配置，SQL 里算不出来）：
`QUALIFICATION`（随机 0.90~1.10）、`ATTRIBUTES`（按等级与资质算出）、以及等级对应的技能，
补完立刻落库。另外旧宠物**不会被弹新手引导**。

通用映射层按 `PRAGMA table_info` 取实际列名，因此遗留列 `LOVE` 会被自动跳过；
`PETDATA.ID` 与模型字段 `player_id` 的差异由 `TABLE_FIELD_ALIASES` 兜住。

`handlers/events.py` 的两个监听器必须是**同步函数**（ATRI 的 `BaseEvents` 拒绝协程），
所以 `database.py` 另外提供了同步的 `load_pet_name` / `load_pet_names`。

## 已知边界

- `achievements.yaml` 只有目录格式，**没有任何代码读取**：任务书 §0 的 15 个 Step 没有
  「成就系统」这一步，§9 也没有它的规范。等立项时直接沿用该目录格式即可。
- 参数校验类提示（性格不合法、行动点不足、属性名错误等）仍在代码里，属于校验信息而非展示文案。
- 轮回的等级门槛只拦「提前主动轮回」；寿命已尽或已满级属于自然终结，即使等级不足也放行，
  否则低等级宠物在寿命结束后会永远无法轮回。
- `/宠物` 聊天仍受框架的 `is_chat_switch_on` / 安全模式 / 测试模式 / 绑定检查约束，
  与合并前一致；插件自身的 `enable` 是额外的总开关。
