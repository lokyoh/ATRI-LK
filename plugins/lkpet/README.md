# lkpet · 赛博宠物养成系统

ATRI-LK 的宠物插件：养成、轮回、肉鸽爬塔统一挂在「宠物」服务下，数据全部走
`database.py` 注册的表。

- **无种族、无进化**：所有宠物共用一套模型，个体差异来自性格与随机资质。
- **天为基本单位**：年龄、寿命、状态衰减、行动点重置全部以个人日推进。
- **每人仅一只**：不可更换、不可多养、不可交易。
- **轮回必须主动确认**：日结算只会提示条件，绝不自动终止或重置宠物。

## 指令

**所有指令都在主命令 `宠物` 之下**，写作 `/宠物.xxx`。这样做的原因：`休息` /
`技能` / `天赋` / `轮回` / `特权` 这类通用词如果占据顶层，任何后续插件想用同一个词都会
撞车 —— 而 nonebot 对**重复的指令前缀只保留第一个**，第二个会被静默丢弃（只打一条 warning）。

> **前缀是动态的**：本文里的 `/` 只是字面示例。运行时实际前缀由
> `ATRI.bot.BotUtils.get_command_start()` 决定（读 `conf.BotConfig.command_start`，
> 可能是 `/`、`！` 等）。插件的全部用户可见文案在 `utils/texts.py` 出口统一做前缀替换
> （`apply_command_start`），改前缀配置无需改任何文案；文档示例仍写作 `/`。

> **日结算全自动**：没有「手动结算」指令。任何会写状态的指令（状态 / 喂食 / 玩耍 /
> 洗澡 / 休息 / 训练 / 肉鸽）在执行**之前**都会先推进过期天数（`_settle_before_action`），
> 因此跨天后的第一个指令一定读到的是**新一天**的行动点与衰减后状态，不会沿用昨天的数值。
> 定时任务（`settle_check_hour`）另外负责离线宠物的推进与「新的一天」推送。

## 配置

### 插件设置 `config.py`

按 `plugins/lkchat/config.py` 的模式定义，**每个字段都有默认值**，用户不改任何一项也能跑：

| 字段 | 默认 | 说明 |
|---|---|---|
| `enable` | `True` | 养成系统总开关 |
| `settle_notify` | `True` | 日结算后是否推送通知（供定时任务使用） |
| `settle_check_hour` / `settle_check_minute` | `0` / `0` | 每日检查日结算的时间 |
| `notify_groups` | `[]` | 接收通知的群号，留空则不主动推送 |
| `tutorial_enabled` | `True` | 是否启用新手引导 |
| `rogue_ticket_item` | `肉鸽入场券` | 肉鸽入场券的 LK 物品名（签到发放、入场自动消耗） |
| `rogue_ticket_per_sign` | `1` | 每次签到发放的入场券张数，`0` = 关闭签到发券 |

**游戏数值不在这里**，全部只放在 `res/data/lkpet/config/*.yaml`，避免两处重复定义。

### 亲密度

量表是 **0–1000**（比常见设计放大 10 倍），这样每日衰减的小数系数乘上基础值 10 之后
仍是整数。**互动获得**：喂食 / 玩耍 / 洗澡 / 休息 统一掷 **3d10**（骰子规格外置
`interactions.yaml` 的 `affection_roll`）；800 以上收益减半、封顶 1000（`core/affection.py`）。
**每日衰减**按「照护是否到位」判定：饱食 / 心情 / 清洁低于阈值、疲劳高于阈值各算一项
未满足，未满足 1 / 2 / 3 / 4 项分别乘 `1.0 / 1.1 / 1.3 / 1.5`，全部满足则不衰减。
判定用的是当天状态衰减**之后**的数值。

**好感加成**：好感越高，**经验与肉鸽战斗输出**越高——线性映射，`0` 好感 0%、
满 1000 好感 **+10%**（上限硬编码在 `core/affection.py` 的 `AFFECTION_BONUS_MAX`），
并且**按加成后的总值向下取整**（`apply_affection_bonus`）。三处消费者共用这一个口径：

| 位置 | 加成对象 | 说明 |
|---|---|---|
| `core/leveling.py` | 训练经验 | 算完状态 / 性格 / 年龄 / 轮回特权各乘区后，最后叠好感 |
| `core/roguelike/battle.py` | 我方每次出手伤害 | 叠在「已按原口径取整的伤害」之上，暴击之前 |
| `core/roguelike/settle.py` | 局内累积经验的结算 | 写回养成数据前统一叠一次，回执数字即实得 |

取整口径是**对总值 floor**，不是「先取整增量再相加」——后者会丢掉小数部分。
好感为 0 时三处都与不加成时逐点一致，所以不会顺带削弱基线数值。
`/宠物.好感度` 会显示当前档位对应的加成百分比。

> **关于「饱食」**：状态在 UI 与文案里一律叫**饱食**（越大越饱，喂食 +38）。
> 数据库列与配置键沿用历史名 `hunger`，语义就是饱食值，因此存量数据无需迁移；
> 代码里看到 `pet.hunger` 请按「饱食」理解。

### 行动点预算与训练平衡

每天 **10 点行动点**（`daily.yaml` 的 `action_points.max_per_day`，00:00 重置）。
喂食 / 玩耍 / 洗澡 / 休息 各 1 点，**训练 2 点**，肉鸽入场**有券 0 点 / 无券 3 点**（推进每层 0 点）。

训练的真实开销不只是 2 点行动点：一次训练扣饱食 / 加疲劳 / 降心情，之后要靠互动补回来，
所以「训练 + 补状态」才是一次完整循环的成本。2026-10-18 按此口径调过一次平衡
（`interactions.yaml` 顶部有同样的记录）：

| | 训练消耗 | 四项回复 | 常规照护下 |
|---|---|---|---|
| 调整前 | 饱食 −15 / 疲劳 +15 / 心情 −10 | 喂食 30 / 休息 20 / 玩耍 10 / 洗澡 30 | 约 **2.35 次/天** |
| 调整后 | 饱食 −10 / 疲劳 +12 / 心情 −7 | 喂食 38 / 休息 25 / 玩耍 13 / 洗澡 38 | 约 **3.03 次/天** |

**训练的资源门槛**（`interactions.yaml` 的 `effects.train.requirements`）：
训练不是「有行动点就能点」的动作。判定按**训练之后**的值算，三项必须同时满足
——饱食 ≥ `hunger_min`（30）、心情 ≥ `mood_min`（30）、疲劳 ≤ `fatigue_max`（80）
——否则整条指令直接拒绝，并在提示里写明差多少、该先做哪个互动。门槛与每日好感衰减
用的是同一套照护阈值，所以不会出现「练完刚好掉出照护线、第二天平白掉好感」。
判定发生在**扣行动点之前**，被拒绝时宠物状态与行动点都不变；只作用于训练，
其余互动不受影响。

一次训练的状态损失总量 40 → 29（−28%），经验收益约 +49%。**行动点消耗没有改动**
（训练仍 2 点），失控风险最低；保守照护（状态接近阈值就先补）下也从 1.17 提升到 1.87 次/天。
亲密度衰减机制不受影响：完全不照护 20 天仍照常扣约 106 点好感。

## 技能系统

技能分**主动 / 被动**两类，宠物同时维护**收集池**与**装备槽**两套数据
（`PETDATA.SKILLS` / `SKILL_EQUIPPED` / `SKILL_SOURCES` / `SKILL_GRANTS`，见 `core/skills.py`）：

| 字段 | 含义 |
|---|---|
| `pet.skills` | **收集池**：已掌握的全部技能，无上限；只在轮回时按来源裁剪 |
| `pet.skill_equipped` | **装备槽**：主动 4 个 + 被动 4 个（`skills.yaml` 的 `limits`） |
| `pet.skill_sources` | 技能 id → 来源，决定轮回保留 |
| `pet.skill_grants` | 等级里程碑已发放计数（幂等，轮回归零） |

**战斗与被动加成只结算装备中的技能**；未装备的留在技能库里，用
`/宠物.技能 装备 <名字>`、`/宠物.技能 卸下 <名字>` 随时更换（槽满需先卸下）。

### 发放规则

| 来源 | 规则 | 轮回后 |
|---|---|---|
| `starter` | 开局技能（撞击），创建与每次轮回后都发 | 保留（每世重发） |
| `regular` | **每 5 级**从常规池抽 1 个主动；**每 10 级**抽 1 个被动 | 清空 |
| `reincarnation` | **满级（100 级）轮回时**从轮回池额外抽 `grants.reincarnation_draw` 个（默认 1） | **保留** |
| `rogue` | 肉鸽每阶段首次击败精英 / 首领各 1 个 | **保留** |

- 里程碑按 `pet.level // every` 计算，所以**一次升多级会补齐**、旧存档**首次读档也会补齐**；
  用 `skill_grants` 计数保证重复调用不重复发放。池子抽空后自然停发（常规池 20 主动 / 10 被动）。
  新技能会在训练 / 肉鸽结算回执里提示；装备槽已满时额外提示去 `/宠物.技能` 调整。
- **轮回时只保留轮回技能与奖励技能**：`apply_reincarnation_retention` 按来源裁剪，
  开局 / 常规 / 旧档技能全部清空，熟练度同步裁剪、里程碑计数归零，
  并**优先保留玩家原来的装备搭配**，空位再自动补满。
- **满级轮回**按「轮回前」的等级判定（`reincarnation.yaml` 的 `max_level`）：
  从 `pools.reincarnation`（10 主动 + 10 被动）额外抽 `grants.reincarnation_draw` 个跨世保留（默认 1）。

### 配置结构（`skills.yaml`）

```yaml
limits:   { active_slots: 4, passive_slots: 4, ... }   # 装备槽与熟练度
grants:   { active_every: 5, passive_every: 10, reincarnation_draw: 1 }
pools:
  starter:      [tackle]
  regular:      { active: [...20], passive: [...10] }
  reincarnation:{ active: [...10], passive: [...10] }   # 跨世保留
skills:        # 列表，每条带 **稳定 id**
  - { id: tackle, name: 撞击, type: active, power: 30, ... }
```

**`id` 是稳定引用键**：旧存档的收集池、肉鸽奖励、池子列表都靠它引用。
重做某个技能的内容（改名、改数值、甚至主动↔被动）时**保留同一个 id** 即可，
玩家已掌握的那个技能会就地变成新内容，不会凭空消失；新增技能才需要新 id。

主动技能支持 `power / strikes（多段）/ leech（吸血）/ mp_cost / cooldown / effects（回血、回蓝）`；
被动技能的 `effect` 可用 `atk / def / spd / mp / max_hp / crit_rate / dmg_mult`（平值相加）。

## 附加玩法

### 肉鸽爬塔（`/宠物.肉鸽`）

- **100 层 = 5 个区域 × 20 层**：青草平原 → 迷雾森林 → 熔岩洞窟 → 冰封王座 → 深渊之巅，
  每区域一个主题，敌人数值跨区**翻倍**（基础 HP 40 → 1000）。
- **普通层三选一**（`roguelike.yaml` 的 `floor_choice` 块）：
  - **商店规则优先**：允许出现的层（区域前 5 层之后，`shop.no_before_gap`）按 `shop.chance`（0.25）
    逐层判定（seed 可复现），**不再每层必出**；一旦刷出，商店**必定**占第 1 个名额，
    先于事件判定定下来，不参与概率抽取。
  - **事件判定**：除商店外的选项**按顺序**用 `event_chance`（`0.1` / `0.2` / `0.3`）逐个判定，
    **只会出现一个事件**——一旦命中就停止，后面的选项直接成为战斗。因此第 1 位命中即 10%，
    第 2 位 90%×20% = 18%，第 3 位 90%×80%×30% = 21.6%；无商店的层总事件率 ≈ 49.6%，
    有商店的层 ≈ 28%。
  - **战斗位默认填入不同敌人**：普通层从该区域敌人池（`region.monsters`，每区域 10 只）抽**互不相同**的敌人，
    所以同一层的两条战斗路线不会是同一只怪；抽中的敌人下标存进 `pending.enemies`，
    选项预告与实际开战的敌人严格一致。
  - **排列**：生成顺序即展示顺序（商店第 1 位、其余顺延），不再打乱。
  - **精英层同样预抽敌人**：精英遭遇的生成规则不变（30% 概率 + 保底、区域级 seed、每区至多 4 次），
    但层内各战斗位从 `region.elites` 抽**互不相同**的精英——同一层的两条精英路线不会再是同一只怪。
- **每区域第 10 层为固定遗物奖励层**（三选一，**仅本局生效**）；**每区域末层只有一个内容：随机一个候选首领**
  （seed 可复现），击杀掉**该 Boss 的专属遗物**（一个 Boss 对应一件），首通另给装备 / 称号（首领层 20/60/100）。
- **每阶段的技能奖励（`stage_skill_rewards`）**：塔的 5 个区域各配 **2 个技能** ——
  **首次击败该区域精英** 送 1 个（青草平原是「肉鸽斩击」），**首次击败该区域首领** 送 1 个。
  首通记录写在 `PETROGUE.UNLOCKED`，键为 `elite:<区域id>` / `boss:<区域id>`，幂等不重复发放；
  奖励技能进**技能库**并尽量自动装备，来源标记为 `rogue`，**跨轮回保留**。
- **精英遭遇**：每区域 5 个精英备选（共 25 个）；区域前 5 层不生成、**每区域至多 4 次**、**倒数第二层必出**
  （30% 概率 + 保底，区域级 seed 复现）；精英 ×1.6 属性、掉落 ×2，战斗行预告「⚠️ 精英出没」。
  精英层的多个战斗位从精英池抽互不相同的精英（旧存档没有预抽下标，仍走 rng 生成兜底）。
- **首领前一层只有一个内容：回血补给事件**（无三选一；回血按区域倍率放大）——吃完直接前进打首领。
- **战斗选中即开战**（普通/精英遭遇没有二次确认；首领报告随机结果后回复 1 开战）。
- **战斗机制（ATB）**：个人攻击条上限 100、每**帧**攒 `gauge_rate_mult × spd`，先满者出击——**速度决定出击频率**；
  技能有 `cooldown`（单位=计时条周期），**战斗计时条每帧 +10、每满 100 全技能冷却 -1**（预留计时 Buff 递减位）；
  战报展示双方出击次数。
  > **帧 vs 回合（两个单位，别混用）**：`帧`是内部时钟（攻击条、冷却、DoT、削弱消退、
  > 循环上限都按帧）；`回合`是对外计时单位 = **战斗计时条走满一次** =
  > `frames_per_turn = 100 / timer_gain = 10` 帧，`BattleSession.turn` 用
  > `ceil(帧数 / 10)` 换算，`BattleResult.rounds` 回报的也是它。
  > 战报行首 `回合N`、胜/负/平局的 `（N 回合）`、`battle_pace` 的 `共 N 回合` 全部走回合；
  > 内部帧号**绝不出现在用户可见文案**里（旧版把帧号当回合显示，于是 ATB 入场头几帧
  > 无人满条时会从「回合2」开始）。`max_rounds: 500` 单位是回合，换算成
  > `max_frames` 后用于循环上限；实测战斗只跑 2~12 帧（不到 2 回合），该上限仅兜异常僵持。
  > 改文案时不要写「R{N}」或「第 N 轮」。
- 每区域 **30 个事件**、**10 种小怪**（共 150 事件 / 50 小怪），事件只从本区域**未触发过**的池里抽
  （一次 run 每个事件只触发一次）。**选项历史剧透**：玩家选过的事件选项跨 run 记录在
  `PETROGUE.CHOICES`（`"事件id:编号"`，仿 RELICS 图鉴，随 ROGUE_VERSION 升到 2 时迁移补列），再次遭遇
  同一事件时，选过的选项文本后自动附 `[实际效果]` 标注（如 `1. 缒下去探看 [HP-14，金币+20]`；
  无效果选项标 `[没有效果]`，遗物掉落带属性说明；补给层回血按区域倍率放大后标注）——
  没选过的选项保持悬念。
- **怪物特点**：50 只小怪与 25 个精英各自带 0-2 个特点（`roguelike.yaml` 的 `monster_traits` 定义块
  + `monsters/elites[].traits`）。**两处展示分层，不要混用这两个函数**：
  - **楼层路线预告**（三选一选项行 / 精英预告 / 首领开战提示）用 `_monster_label` →
    `名称（特点）`。选项行**不再套外面那层括号**（`battle_hint: "：{monster}"`、
    `elite_hint: "：⚠️ {monster}"`），避免嵌套括号：`1. 战斗：稻草傀儡（血厚，速慢）`、
    `1. 战斗：⚠️ 铁角原牛（攻高）`。
  - **战斗详情**（战报标题、胜利/失败行）用 `_monster_name` → **纯名字**，特点另起一行
    `🔹 特点：血厚，速慢`，避免与玩家技能括号混在一起显得嘈杂。
  - 描述行 `—— {desc}` 走 `_monster_desc`，小怪/精英/首领统一按 `desc` 渲染，
    没有描述就整行省略（50 只小怪都已补写描述）。
  数值特点（血厚/薄、攻高/低、防高/低、速快/慢，即 `*_mult` 乘区）在生成时作用于当层公式
  （精英/首领倍率之前，单次叠乘；首领不叠小怪特点）；行为特点直接进入 ATB 战斗：
  `群袭`（一次出击 2 击、每击 0.6×）、`高暴击`（25% 概率 ×`battle.crit_mult`）、
  `吸血`（造成伤害的 30% 回复自身，封顶生成时生命）、`棘刺`（我方打出伤害的 20% 反弹到局内生命，
  不致死）。同区域小怪特点签名 ≥6 种（冒烟校验「不是同一个模子刻出来的」）。
- **敌方专属技能（只有精英与首领有）**：小怪永远只有普攻；技能表**单独放在 `roguelike.yaml` 的
  `enemy_skills`**（共 30 个，分 物理猛击系 / 蓄力终极技 / 状态与削弱系 / 自我强化系 / 召唤系 五组；
  **故意不写进 `skills.yaml`**，那是宠物自己的技能表），精英在 `elites[].skills` 引用、首领在
  `bosses[].skills` 引用。字段与宠物技能同口径：`power`（伤害 = atk × power / 30，与小怪普攻同一基准）、
  `strikes`、`crit_rate`、`leech`、`heal`、`self_buff`、`debuff`、`dot`、`charge`、`interrupt`、`summon`、
  `cooldown`（单位 = 计时条周期）、`mp_cost`、`priority`（越大越优先，同级比 `power`）。
- **敌方 MP**：独立资源池，入场即满（`battle.enemy_mp`：基础 50，精英 ×1.6 / 首领 ×2.4 / 召唤物 ×0.6），
  之后**计时条每满一次回复 `regen`（8 点）**——与技能冷却同一节奏。
- **我方 MP（局内跨层资源）**：`battle.mp`。**不再每场战斗重置**，规则三条：
  - **入场满蓝**，上限 = 养成 `mp` ×（遗物 `mp_mult`）+ 被动 `mp` + 遗物平值 `mp`
    （`_common.rogue_mp_max`，战斗与进度展示同一口径）；
  - **每前进一层回复上限的 `per_floor_pct`（20%）**；
  - **每个战斗回合结束时回复上限的 `per_turn_pct`（5%）**——触发点是**计时条走满**
    （回合结束），不是我方每次行动：一回合内双方可各行动 8~10 次，挂在行动上会变成
    「每出手都回蓝」，战报里一个回合冒出好几条「魔力回复」。**开局那一回合不回复**，
    回补从第 1 回合结束之后开始；
  - **休息层**（区域倒数第二层，即首领前的补给层，无战斗）在 20% 之上**额外** `rest_floor_pct`（40%）。
  战斗结束把当前值写回 `run.mp`（`_do_battle`），所以打塔是一路攒着蓝走的。
  事件可回蓝：`effect.run_mp`（固定值）与 `effect.run_mp_pct`（上限百分比），可同时使用。
- **技能耗蓝**：`skills.yaml` 的 `mp_cost` 是主要制约。强技能更贵（终焉审判 52、星陨/万象风暴 44、
  以太爆裂 40），回蓝技**不再净赚蓝**（聚魔弹 30 耗回 28、灵脉 8 耗回 20、轮回汲取 24 耗回 16），
  否则「回蓝技无限续」会把整条蓝量经济架空。
- **「不可行动」（打断蓄力后的硬控）**：`battle.unactionable`。这是本插件**唯一**一种硬控状态，
  统一叫「不可行动」（旧的「眩晕」命名已废弃，不要再用）。
  - 触发：**蓄力技被打断时**（`_charge_taken` → `_apply_unactionable`）施加给该单位；
  - 数值单位是**速度点** = `目标当前速度 × 回合数`。每轮**先用速度抵扣**，抵扣完的剩余速度才进行动条，
    所以控制期间它既攒不动条、也吃掉了当轮本会攒的那份；抵扣归零即解除；
  - 同时 `reset_gauge`：清空它已攒的行动条，并**取消它本轮的出手**（只清条不取消的话，
    它本轮早已排进队列、照样出手，「打断」就毫无意义）；
  - 配平旋钮（全部在 `roguelike.yaml`）：`default_rounds` / `max_rounds`（单次上限）/
    `stack_limit_rounds`（**一场战斗累计上限**，挣脱后不清零，防止无限连控）/
    `boss_resist`（首领抵抗 0.8）/ `charge_bonus`（蓄力越久罚越重：额外 = `(charge-1) × 0.5`）；
    每个蓄力技也可自己写 `unactionable`（冲锋撞角/大地震击 1.0，陨火坠击/湮灭之息 1.5）。
  - **配套 HP 补偿**：控制等价于让首领少出手，因此 5 个带蓄力技的首领上调了 `hp_mult`
    （暴走野猪王 2.4→2.7、熔岩巨人 4.2→4.7、火蜥领主 3.0→3.5、极光巫妖 3.0→3.5、虚空吞噬者 3.6→4.2），
    按「每 1 回合控制 ≈ 补 12% 生命」折算。无蓄力技的首领不受影响（对照组实测无差异）。
- **蓄力终极技（可打断）**：敌方花一次行动开始蓄力，**蓄力期间可被打断**：蓄力期间我方对它造成的
  **累积伤害** ≥ 自身生命上限 × `interrupt` 即取消蓄力，否则再过 `charge` 次行动释放。例：精英 铁角原牛
  的「冲锋撞角」（power 72、charge 2、interrupt 0.16）——打断窗口就是这套机制留给玩家的真实战术空间；
  打断成功还会给它挂上「不可行动」（见上），这是打断真正的收益所在。
- **形态 / 阶段（`enemy_phases`）**：生命比例 ≤ 该阶段 `at_hp` 时触发**一次**（每个阶段各自只触发一次），
  施加**永久**属性乘区，可选附加回血与追加技能；战报会播报进入的形态（暴怒 / 狂乱 / 坚壁 / 疾走 / 不灭 /
  垂死挣扎）。精英用单个形态（`elites[].phase`，如 雾隐枭人 → 疾走），首领用列表（`bosses[].phases`）。
  例：深渊首领 无名之影 `skills: [e_summon_shade, e_soul_reap, e_shadow_raid]`、
  `phases: [ph_swift, ph_berserk]`（先 疾走 再 狂乱）。
- **召唤与转火**：召唤系技能往场上加援军，援军与召唤者并肩作战、**召唤者倒下时一并消失**；我方自动攻击
  **存活敌人中生命比例最低者**（比例相同优先首领），所以**先清召唤物再打首领**才是正解；同时存在的敌人
  数由 `battle.max_units`（4）封顶，超出则不再召唤。
- **削弱与持续伤害（DoT）**：削弱时长单位 = 计时条周期数（`debuff.rounds`）；DoT 每轮结算一次、
  **自身不致死**（最多把局内生命压到 1），所以只有正面攻击能结束本局。
- **逐回合战报**：战报新增最近若干轮的逐条回放——谁施放了什么技能、蓄力进度与是否被打断、进入形态、
  召唤、我方转火、暴击、吸血与 DoT 结算，输赢原因一眼可见；回放条数上限 `battle.log_limit`（12，0 = 关掉）。
- **战前预告**：精英 / 首领遭遇会先列出对手的专属技能（附 `蓄力 N 回合，累积伤害可打断` / `召唤 N 只` /
  `削弱我方` / `耗蓝 N` 等标注）与形态阈值（`形态名（生命 ≤N%）`），进场前就知道该防什么。
  一个技能有多个机制时会**一起列出**（「自我回复，耗蓝 15」）；**没有任何机制的技能只显示名字**，
  不会再渲染成 `技能名（）` 这种空括号。
- **遗物系统（95 件，仅本局生效）**：普通 35（遗物层三选一池）+ 稀有 15 + 商店专属 20 + 事件专属 10 +
  Boss 专属 15（`rogue_relics.yaml`），本局获得即时生效；`PETROGUE.RELICS` 只作「见过的遗物」**图鉴**，
  不提供加成。效果为战斗属性/掉落乘区、暴击率、商店折扣、事件掉落、首领战后回血等，**不改养成数据**。
  所有遗物展示位（三选一 / 获得回执 / 商店货架 / 路线预览 / 进度列表）名称后自动附**紧凑属性说明**
  （如 `微光护符（攻击+6）`、`傀儡之心（防御+15%，生命上限+10%）`），由 `core/roguelike.py` 的
  `relic_effect_note()` 按 `effect` 键实时生成——不需要在 YAML 里另写一份。
- 局内生命 / 金币 / 增益只存在于 run 状态，**只在结算时刻**写回成就点与首通奖励。
- **遗物商店**：区域前 5 层不刷出，之后每层按 `shop.chance`（0.25）判定是否刷出、刷出即占三选一第 1 位；
  货架固定 3 件 = 普通 1 + 稀有 1 + 商店专属 1（排除本局已持有），
  价格按稀有度 `shop.tier_price`（25/60/50）；商店只卖遗物，回血由事件与补给承担。
  - **折后价（乘算）**：持有带 `shop_discount` 的遗物时，**成交价 = 基础价 × 本局所有 `shop_discount` 的乘积**
    （多件折扣**叠乘不相加**，最低 1 金）。商店正文、楼层三选一里的货架摘要与实际扣款**同一口径**
    （`run_state._final_price`），有折扣时正文顶部给出「折扣生效中」提示，行尾附「（原价 N 金）」。
  - **已购买标记**：买过的遗物在本局商店货架里继续显示但**标注「已购买」**，重复购买会被拒绝
    （`relic_owned`）；商店正文在购买后立即重渲染，标记与新折扣同步生效。
  - **无「开局金币」属性**：遗物表不再有 `start_coins`，局内金币只靠战斗/事件获取；原本带该属性的
    9 件遗物已重做为 `coins_mult` / `shop_discount` / 属性类效果，不是空壳。
- **每日入场券（签到联动）**：`/宠物.肉鸽 开始` 会**先检查 LK 背包里的「肉鸽入场券」**——
  有券就自动消耗 1 张且**当次入场不消耗行动点**；没券才按原规则扣 3 点行动点。
  券是 **LK 账户物品**（`plugins/lkpet/items.py` 定义，`item_loading_events` 时注册），
  **每日签到发放 1 张**（`sign_in_events` 钩子，张数由插件设置 `rogue_ticket_per_sign` 控制，
  设为 0 即关闭），所以「每天一次免费入场」直接绑定在签到习惯上；多余的券可以攒着。
  撤退会按到达层数结算并结束本局，**下次入场重新判定券/行动点**。
- **行动点**：有券入场 0 点、无券 3 点，推进每层 0 点（打到哪算哪，明天再来）。
- **养成接入**：战斗读取 `pet.attributes`（天赋加成直接生效）；主动技能自动施放 ——
  治疗技能血量 <50% 优先，伤害技能按「威力 × 熟练度 ÷ 30」换算攻击系数且**施放即涨熟练度**，
  每技能有 `cooldown`（计时条周期，每满 100 全体 -1）；
  **只结算装备中的技能**（主动 4 槽 / 被动 4 槽，见下节「技能系统」）。
- 数值全在 `roguelike.yaml` + `rogue_events.yaml` + `rogue_relics.yaml`：**改数值只动 YAML**
  （精英/首领技能与形态见 `roguelike.yaml` 的 `enemy_skills` / `enemy_phases`），
  用户可见文案统一在 `texts.yaml` 的 `rogue` 块，代码里不写死。

## 数据表

数据库为 `data/sql/lkbot.db`，`database.py` 是以下四张表的唯一注册方：

| 表 | 主键 | 说明 |
|---|---|---|
| `PETDATA` | `ID` | 宠物主表（`NAME` / `INSTRUCTION` + 全部养成字段；遗留列 `LOVE` 不读取） |
| `PETREINCARNATION` | `PLAYER_ID` | 轮回与成就点 |
| `PETBIOGRAPHY` | `PLAYER_ID` | 传记 |
| `PETROGUE` | `PLAYER_ID` | 肉鸽进度：历史统计、首通解锁、遗物图鉴（RELICS）、事件选项历史（CHOICES，跨 run）、进行中的 run |

> **遗留表**：已部署库中的 `PETTRPG` 表（跑团系统遗留）暂时保留在磁盘上，代码不再注册。
> 下次数据库迁移时执行 `DROP TABLE IF EXISTS PETTRPG` 清理，详见 `database.py` 头部的「数据库变更计划」。

**迁移机制**：每张表带版本号（`PETDATA_VERSION` = 1，`ROGUE_VERSION` = 2）。加载时版本号
与库中记录不一致就跑对应的 `update_*_db`：它**不看版本号本身**，而是读 `PRAGMA table_info`
把所有缺失的列 `ALTER TABLE` 补齐（幂等，可重复执行），然后把版本号写为新值。
**改表结构必须同步提升版本号**，否则已到当前版本的库会因"版本相同"跳过迁移、拿不到新列。
`PETDATA` 迁移同时把 `ADOPTED_AT` / `CYCLE_STARTED_AT` / `LAST_SETTLEMENT_AT` 的空值填成迁移
时刻（用 `ATRI.utils.datetime.now()`，与插件其余部分同一时区）。

- **亲密度只有一个来源**：`AFFECTION`（0–1000 量表）；遗留列 `LOVE` 原样留在表里，
  不换算、无代码读取，通用映射层按实际列名取数会自动跳过它。
- **存量宠物首次被读取时**会补全无法由 SQL 计算的字段（属性依赖 `pet.yaml`）：
  `QUALIFICATION`（随机 0.90~1.10）、`ATTRIBUTES`（按等级与资质算出）与技能存储
  （收集池 / 装备槽 / 来源 / 里程碑按当前等级补齐），补完立刻落库；存量宠物不弹新手引导。
- `PETDATA` v1 → v2 的技能迁移：旧的 `SKILLS` 列（既是已学也是已装备）原样复制进**收集池**，
  装备槽取各类型前 4 个（多出来的留在收集池可再装），来源统一按池子归属重新推导。
- `PETDATA.ID` 与模型字段 `player_id` 的差异由 `TABLE_FIELD_ALIASES` 兜住。

`handlers/events.py` 的监听器（含签到发券）必须是**同步函数**（ATRI 的 `BaseEvents` 拒绝协程），
所以 `database.py` 另外提供了同步的 `load_pet_name` / `load_pet_names`。

**LK 账户数据必须在 `with` 块内改**：`user_manager.get_user_data()` 返回的是未加锁副本，
只有 `with ... as user:` 退出时 `__exit__` 才会把改动落库。扣入场券就写在 with 内，
否则券只在内存里少掉、数据库仍保留。

## 已知边界

- `achievements.yaml` 只有目录格式，**没有任何代码读取**：任务书 §0 的 15 个 Step 没有
  「成就系统」这一步，§9 也没有它的规范。等立项时直接沿用该目录格式即可。
- 参数校验类提示（性格不合法、行动点不足、属性名错误等）仍在代码里，属于校验信息而非展示文案。
- 轮回的等级门槛只拦「提前主动轮回」；寿命已尽或已满级属于自然终结，即使等级不足也放行，
  否则低等级宠物在寿命结束后会永远无法轮回。
- `/宠物.聊天` 受框架的 `is_chat_switch_on` / 安全模式 / 测试模式 / 绑定检查约束；
  插件自身的 `enable` 是额外的总开关。
